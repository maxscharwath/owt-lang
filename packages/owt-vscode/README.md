# OWT for Visual Studio Code

Language support for [OWT](https://github.com/maxscharwath/owt-lang) — the compiled, reactive UI language of `.owt` components.

```owt
import { onMount } from 'owt'

export component Counter(props: { start?: number }) {
  var count = props.start ?? 0
  val doubled = count * 2

  <button onClick={() => count++}>Clicked {count} times ({doubled})</button>

  if (count > 10) {
    <p class:warn={true}>That's a lot of clicks</p>
  }

  <style>
    .warn { color: crimson }
  </style>
}
```

## Features

- **Syntax highlighting** for the whole language: module-level TypeScript, `component` declarations (props object, destructured, named props with defaults, generics), `var` / `val` state, markup (elements, components, `Icons.Plus`-style dotted components, fragments, `<slot>` outlets, `<window>` / `<document>` / `<head>` / `<body>`), attributes and directives (`bind:`, `class:`, `style:`, `use:`, `on:`, `onClick`-style events, `{...spread}`, `{shorthand}`), `{expressions}`, control flow (`if` / `else`, `for … of [rev] a..b, meta; track key` / `empty`, `switch` / `case … if (guard)` / `default`, `await` / `then` / `catch`, `try` / `catch (error, reset)`, `key`), slot definitions (`slot header({ title }) { … }`), `<!-- comments -->` and scoped CSS in `<style>` (including `:global(...)`). Embedded TypeScript and CSS use VS Code's own grammars.
- **IntelliSense from the OWT language server** (`@owt/language-server`, built on Volar): type checking and diagnostics, completions, hover, go to definition, references, rename, code actions, formatting and more — everything TypeScript knows about the code in your components. Closing tags are inserted automatically when the server offers auto-insertion.
- **TypeScript integration**: a TypeScript server plugin (`@owt/typescript-plugin`) makes `.ts` / `.tsx` files understand `import { Counter } from './Counter.owt'` with full types.
- **Show Compiled Output**: the JavaScript (and scoped CSS) generated by `@owt/compiler`, side by side and updated as you type.
- **Show Virtual TypeScript Code**: the TypeScript the language server generates for a component — useful when a diagnostic looks surprising.
- **Snippets** for components, state, every control-flow block, slots, styles and `onMount`.
- Editor configuration: comment toggling, bracket matching and auto-closing, indentation after `{` and opening tags, folding (`// #region`, `<!-- #region -->`).

## Commands

| Command | Description |
| --- | --- |
| `OWT: Restart Language Server` | Restarts the language server (re-reading `owt.server.path` and the TypeScript version). |
| `OWT: Start Language Server` / `OWT: Stop Language Server` | Starts or stops the language server. |
| `OWT: Show Language Server Output` | Opens the server's output channel. |
| `OWT: Show Compiled Output` | Opens the compiled JavaScript of the current file in a read-only editor (`owt-compiled:` documents). Also in the editor title bar. |
| `OWT: Show Virtual TypeScript Code` | Shows the virtual TypeScript of the current file (`owt-virtual:` documents, via the `owt/virtualCode` request). |
| `OWT: Select TypeScript Version...` | Chooses between VS Code's TypeScript and the workspace version (`typescript.tsdk`). Also available from the TypeScript version item in the language status bar. |
| `OWT: Find File References` | Finds the files that import the current component (also in the explorer context menu). |
| `OWT: Reload Projects` | Reloads the TypeScript projects in the language server. |
| `OWT: Open Settings` | Opens the extension's settings. |

The **OWT** item in the status bar (visible for `.owt` files) shows the server state; click it for a menu of these actions.

## Settings

| Setting | Default | Description |
| --- | --- | --- |
| `owt.server.path` | `""` | Path to a custom build of the language server (`@owt/language-server`'s `dist/index.js`, or its package folder). Relative paths resolve against the first workspace folder. Ignored in untrusted workspaces. |
| `owt.trace.server` | `"off"` | Traces the LSP traffic (`off`, `messages`, `compact`, `verbose`) in the *OWT Language Server Trace* output channel. |
| `owt.compiledOutput.dev` | `false` | Compile in development mode for *Show Compiled Output*. |

The extension also sets `editor.wordBasedSuggestions` to `off` for `[owt]`, so completions come from the language server only.

### TypeScript version

The language server runs on VS Code's bundled TypeScript by default. To use the workspace version, set `typescript.tsdk` (for example `"node_modules/typescript/lib"`) and pick **Use Workspace Version** with **OWT: Select TypeScript Version...**. The workspace version is only loaded in trusted workspaces.

## How it fits together

```
 VS Code
 ├─ owt-vscode (this extension, dist/extension.js)
 │   ├─ TextMate grammar, snippets, language configuration
 │   ├─ LSP client (vscode-languageclient + @volar/vscode) ──IPC──► server/index.js
 │   │                                                              (@owt/language-server, Volar 2.4,
 │   │                                                               initializationOptions.typescript.tsdk)
 │   └─ @owt/compiler (bundled) ─► "Show Compiled Output"
 └─ TypeScript extension (tsserver)
     └─ node_modules/@owt/typescript-plugin  ◄─ contributes.typescriptServerPlugins
        (lets .ts files import .owt components with full types)
```

- The **client** starts `server/index.js` as a Node module over IPC with `initializationOptions: { typescript: { tsdk } }`, shows its state in the status bar and wires Volar's editor helpers (auto-insertion, document drop edits, file references, project reload, [Volar Labs](https://marketplace.visualstudio.com/items?itemName=johnsoncodehk.volarjs-labs) support — the extension exports the Labs API).
- The **TypeScript plugin** is loaded by VS Code's TypeScript extension (also for workspace TypeScript versions); it is not started by this extension.
- The **compiler** is bundled into `dist/extension.js` and only loaded the first time compiled output is requested.

## Development

The extension lives in the OWT monorepo (`packages/owt-vscode`). From the repository root:

```sh
pnpm install
pnpm build                       # builds the workspace packages (@owt/compiler, @owt/language-server, @owt/typescript-plugin, …)
pnpm --filter owt-vscode build   # bundles the extension
```

`pnpm build` in this package (`scripts/build.mjs`):

1. bundles `src/extension.ts` with esbuild into `dist/extension.js` (CommonJS, `vscode` external, `@owt/compiler` included),
2. copies `packages/owt-language-server/dist` to `server/`,
3. copies `packages/owt-typescript-plugin` (`package.json` + `dist/`) to `node_modules/@owt/typescript-plugin/`.

A missing language server or TypeScript plugin is a warning in development builds and an error with `--production`. `OWT_LANGUAGE_SERVER_DIR` / `OWT_TS_PLUGIN_DIR` point the build at other checkouts of those packages.

Other scripts:

| Script | Description |
| --- | --- |
| `pnpm watch` | Rebuilds the client on change (the server and plugin are copied once). |
| `pnpm typecheck` | `tsc --noEmit`. |
| `pnpm test:grammar` | Grammar snapshot tests (`test/grammar/*.owt` → `*.owt.snap`) and scope assertions (`test/grammar/assertions/*.owt`), run with `vscode-tmgrammar-test` against the TypeScript/CSS grammars from `tm-grammars`. |
| `pnpm test:grammar:update` | Regenerates the snapshots after an intended grammar change — review the diff. |
| `pnpm package` | Production build + `vsce package --no-dependencies` → `owt-vscode-<version>.vsix`. Because vsce never packages `node_modules/` in that mode, `scripts/inject-ts-plugin.mjs` then adds `node_modules/@owt/typescript-plugin` to the VSIX. |
| `node scripts/generate-icon.mjs` | Re-renders `images/icon.png`. |

To debug, open `packages/owt-vscode` in VS Code and run **Run OWT Extension** (F5); **Attach to OWT Language Server** attaches to the server's inspector on port 6009. Install a packaged build with `code --install-extension owt-vscode-<version>.vsix`.

> The VS Code Marketplace does not accept SemVer pre-release versions such as `1.0.0-beta.1`; publish with a plain `major.minor.patch` version and `vsce publish --pre-release` instead.
